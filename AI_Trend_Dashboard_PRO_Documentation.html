Step 2

Module Deep Dives

📈 Trend Engine

EMA 20 · EMA 50 · EMA 200 · Crossover Detection

The core of the system. Uses three EMAs to measure trend alignment. Full bull alignment (price > EMA20 > EMA50 > EMA200) scores 100. Full bear alignment scores 0. Partial states are assigned 75 or 25. The trend score is then blended 50/50 with the MTF average before entering the weighted composite.

  • Golden Cross (EMA20 crosses above EMA200) triggers a dedicated alert
  • Death Cross (EMA20 crosses below EMA200) triggers a dedicated alert
  • Background shading provides visual context for full bull/bear states
  • EMA lines plotted on chart and can be toggled via input

⚡ Momentum Engine (RSI)

RSI · Overbought/Oversold Detection · Momentum Scoring

RSI is calculated using ta.rsi() on closed bars — it does not repaint. The raw RSI value (0–100) is used directly as the momentum score, centered at 50. Values above 70 indicate overbought conditions (caution), and below 30 indicate oversold (potential bounce).

  • Healthy bullish momentum: RSI 50–70 (trending without being overextended)
  • Healthy bearish momentum: RSI 30–50
  • Overbought (RSI ≥ 70): score still high, but label warns of exhaustion
  • Oversold (RSI ≤ 30): score still low, but label signals reversal potential

📊 Volume Engine

Volume Ratio · Directional Spikes · Trend Confirmation

Volume is compared to a 20-bar SMA to produce a ratio (e.g. 1.8 = 180% of average). This ratio is scaled into a 0–100 score. Directional adjustment: if a spike occurs on a bullish candle (close ≥ open), the score is boosted 20%. On a bearish spike, it is reduced 20%. This rewards volume that confirms rather than contradicts trend direction.

  • vol_ratio = current volume / vol_ma (guarded against division by zero)
  • Spike threshold configurable by user (default 1.5× average)
  • Dashboard shows ratio in real-time alongside the label
  • Extreme spikes (2.25×+) labeled as "Extreme Spike"

🌊 Volatility Engine (ATR)

ATR · ATR MA Ratio · Low-Volatility Filter

ATR measures the true range of price movement. By dividing the current ATR by a 20-bar SMA of ATR, we get a relative volatility ratio. This powers two functions: (1) a score contribution (high volatility → higher score as market is active), and (2) a signal filter gate that blocks buy/sell signals during choppy low-volatility periods.

  • atr_ratio < 0.5 (configurable) activates the low_vol_filter gate
  • When filter is active, buy/sell signals are suppressed — not plotted
  • ATR absolute value shown in dashboard for reference
  • Relative ratio used for scoring to normalize across assets

🔗 Multi-Timeframe Engine

request.security() · lookahead_off · 4 Timeframes

Each of the 4 timeframes runs the same EMA alignment logic via a helper function f_mtf_score(). The function uses request.security() with lookahead=barmerge.lookahead_off to prevent lookahead bias. The four scores are averaged into mtf_avg, then blended 50/50 with the current-timeframe trend score.

  • All 4 timeframes shown individually in dashboard with bull/bear/neutral status
  • MTF alignment summary label (e.g. "Full Bull", "Strong Bear", "Mixed")
  • Full bull/bear MTF alignment triggers dedicated alerts
  • Timeframes configurable via input (default: 5m, 15m, 1H, 4H)
MTF helper function — non-repainting pattern 
// NON-REPAINTING: lookahead=barmerge.lookahead_off is critical
f_mtf_score(tf) =>
    e_fast  = request.security(syminfo.tickerid, tf,
                  ta.ema(close, ema_fast_len),
                  lookahead=barmerge.lookahead_off)
    e_slow  = request.security(syminfo.tickerid, tf,
                  ta.ema(close, ema_slow_len),
                  lookahead=barmerge.lookahead_off)
    c       = request.security(syminfo.tickerid, tf, close,
                  lookahead=barmerge.lookahead_off)
    bull    = c > e_fast and e_fast > e_slow
    score   = bull ? 100.0 : ... // etc.
    score
Step 3 — AI Score Engine

Weighted Scoring Model

Each engine produces a 0–100 score. These are combined using a user-configurable weighted average. The weights auto-normalize so they always sum to 100%, even if the user changes them.

Engine Input Variable Default Weight Score Range Weight
Trend (EMA + MTF blend) w_trend 40% 0 – 100
RSI Momentum w_rsi 25% 0 – 100
Volume Confirmation w_vol 20% 0 – 100
ATR Volatility w_atr 15% 0 – 100

Signal Classification

AI Score calculation with normalized weights 
// Normalize weights to always sum to 100%
total_weight    = w_trend + w_rsi + w_vol + w_atr
w_trend_n       = total_weight > 0 ? w_trend / total_weight : 0.40

// MTF blended 50/50 with current-bar trend score
trend_mtf_blend = (trend_score * 0.5) + (mtf_avg * 0.5)

// Weighted composite AI score
ai_score        = (trend_mtf_blend * w_trend_n) +
                  (rsi_score       * w_rsi_n)   +
                  (vol_score       * w_vol_n)    +
                  (atr_score       * w_atr_n)

💡 Dashboard performance tip

The table is built inside an if show_dash block. This is critical — TradingView still evaluates the table.cell() calls on every bar even when the condition is false unless the entire block is wrapped. The var table declaration outside the block ensures the table object persists across bars.

🎨 Dynamic color logic

Score ≥ 70 → lime green. Score 55–70 → green. Score 45–55 → gray. Score 30–45 → orange. Score ≤ 30 → red. The f_score_color() helper applies this mapping to every score badge in one place — change the thresholds there and it updates everywhere.

🔢 table.merge_cells()

Title row and section separator rows use table.merge_cells() to span all 3 columns. This creates visual hierarchy and section dividers without needing extra table rows. Used for the header, the MTF section divider, and the AI Signal section divider.

Step 9 — Alert System

7 Named Alert Conditions

Each alertcondition() has a unique title visible in TradingView's alert creation UI and a dynamic message template using {{ticker}}, {{close}}, and {{plot_0}} (the hidden AI score plot).

🟢 Buy Signal

AI score crosses above the user-defined minimum threshold. ATR filter must be clear (not in low-volatility zone).

🔴 Sell Signal

AI score crosses below (100 − threshold). Same ATR filter gate. Uses ta.crossunder() for clean one-bar triggers.

⭐ Golden Cross

EMA 20 crosses above EMA 200. Classic trend-change bullish signal. One-bar trigger via ta.crossover().

💀 Death Cross

EMA 20 crosses below EMA 200. Classic trend-change bearish signal. Complementary to golden cross.

🚀 Strong Setup

AI score reaches extreme territory (≥ 80 or ≤ 20). Fires every bar the condition is true — best used with "Once Per Bar" in TradingView alert settings.

📈 Full MTF Bull

All 4 timeframes show bullish EMA alignment simultaneously. High-confidence trend confirmation signal.

📉 Full MTF Bear

All 4 timeframes show bearish EMA alignment. High-confidence trend reversal / continuation signal.

Step 6 — Technical Deep Dive

Pine Script Best Practices

01 Avoiding Repainting

Repainting occurs when a script's historical output changes on recalculation. Use barmerge.lookahead_off in all request.security() calls. Never use barstate.isrealtime to calculate indicators — they will show different values on history vs live. Use ta.crossover/crossunder on confirmed values only.

02 request.security() Rules

Always pass the expression to calculate (e.g., ta.ema(close, 20)) as the third argument — do not pass close and calculate inside. Use barmerge.lookahead_off (default in v6). Avoid calling request.security() inside loops or conditional branches — Pine limits the number of unique calls.

03 Dashboard Performance

Declare your table with var so it persists. Build all table.cell() calls inside one if barstate.islast or if show_dash block. Avoid calling table functions inside loops. Use table.merge_cells() for layout rather than creating extra columns. Keep row count under 20 for readability.

04 Pine Script Limitations

Max 40 unique request.security() calls per script. Max 500 labels, 500 lines, 50 boxes per chart. No file I/O, no HTTP requests, no external libraries. Cannot access user's account data. Calculations are always bar-by-bar — no vectorized operations. max_bars_back limits historical lookback.

05 Alert Optimization

Use alertcondition() over alert() for user-configurable triggers. Keep alert conditions as simple boolean expressions — don't compute inside the condition. Use {{plot_0}} to pass computed values into alert messages (requires a plot() call). Use "Once Per Bar Close" for non-repainting alert behavior.

06 Score Normalization

All engine scores output 0–100. This is critical for the composite formula. When adding new engines, always normalize their output to this range first. Use math.min(math.max(raw, 0), 100) as a safety clamp. This prevents any single engine from dominating regardless of its raw value magnitude.
